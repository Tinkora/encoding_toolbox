# Encoding Toolbox 产品规格

## 产品定位

Encoding Toolbox 是面向开发者和 AI Agent 自动化流程的本地编码与摘要工具。它解决的
不是“再做一个在线 Base64 页面”，而是在脚本、Agent tool call 和人工排障之间提供同一套
有边界、可测试、可预测的转换契约。

## 真实使用场景

- Agent 解码 API 或日志中的 Base64/Base64URL 载荷，再将原始字节交给下一步工具。
- CI、下载脚本或人工排障计算文件 SHA-256/BLAKE3，并与发布方提供的值比较。
- 集成调试时使用环境变量中的共享密钥生成 HMAC，避免密钥进入命令参数和输出。
- 开发者在不上传内容的前提下，通过浏览器处理短文本或本地文件。

## 已交付范围

| 能力 | 算法或行为 |
| --- | --- |
| 编码与解码 | Base64、无填充 Base64URL、Base32、Base32Hex、Hex |
| 摘要 | SHA-256、SHA-384、SHA-512、BLAKE3、兼容旧系统的 MD5 |
| HMAC | HMAC-SHA-256、HMAC-SHA-512 |
| CLI | stdin/文件输入、原始字节解码输出、JSON schema 1、稳定错误码 |
| 浏览器 | 文本/本地文件、复制、下载、WASM 本地计算、无持久化 |

MD5 必须显示“不抗碰撞”的警告，只用于旧校验值兼容。摘要匹配不能被描述为文件安全或
来源可信的证明。

## 输入边界

| 边界 | 上限 |
| --- | ---: |
| CLI stdin 或文件 | 100 MiB |
| 浏览器文本 | 1 MiB |
| 浏览器本地文件 | 20 MiB |
| core 解码文本 | 8 MiB |

当前实现一次性读取输入，不宣称流式或超大文件能力。

## 隐私与安全

- 浏览器只加载仓库自身发布的静态 JS/WASM，不上传用户输入。
- 不使用遥测、分析、Cookie、localStorage、IndexedDB、CDN 或第三方运行时资源。
- CLI HMAC key 只能通过 `--key-env NAME` 读取，不接受明文命令参数。
- 所有公开失败均使用稳定错误码；错误不得包含 HMAC key。

## 明确非目标

- 不提供 MCP server，也不把静态 JSON schema 描述为可执行 Agent tool。
- 不替代 CyberChef 这类通用数据转换套件。
- 不提供账户、历史记录、云同步、上传 API 或服务端处理。
- 不自行实现密码学算法，使用成熟 Rust crate 并以已知答案测试锁定行为。
- 不因“算法数量更多”而添加缺少真实工作流和测试向量的功能。

## 验收标准

- RFC 4648 编码向量、全字节输入、空输入和错误 padding 有回归测试。
- SHA、BLAKE3、MD5 与 HMAC 使用公开已知答案验证。
- CLI stdin 与文件输入结果一致，超限文件在读取前拒绝，错误退出码稳定。
- WASM 通过 Node 测试；浏览器在 375、768、1024、1440 像素宽度通过真实操作测试。
- 浏览器测试覆盖键盘、剪贴板、下载、无持久化、无意外外连、控制台和横向溢出。
- README 默认英文并提供中文入口；发布说明只陈述已经验证的能力。
